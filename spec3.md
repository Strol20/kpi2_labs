# Специфікація Use Cases та сценаріїв для Sequence Diagram

## 1. Загальні учасники

Учасники нижче є логічними ролями для Sequence Diagram. Інтерфейс, сервіси та репозиторії деталізують взаємодію, але не є новими сутностями ER-моделі.

| Учасник | Тип | Відповідальність |
|---|---|---|
| `Photographer` | Актор | Створює дописи, прикріплює фотографії та додає теги. |
| `User` | Актор | Відкриває дописи, переглядає фотографії й коментарі, шукає дописи. У сценаріях перегляду це може бути той самий користувач форуму. |
| `ForumUI` | Інтерфейс | Приймає дії користувача та показує результат. |
| `PostService` | Логічний сервіс | Координує створення, публікацію, отримання та пошук дописів. |
| `PhotoStorageService` | Зовнішня система | Зберігає передані фотографії та повертає посилання на них. Назва відповідає актору «Сервіс зберігання зображень» зі `spec2.md`. |
| `PostRepository` | Доступ до даних | Зберігає та отримує записи `POST`. |
| `PhotoRepository` | Доступ до даних | Зберігає та отримує метадані `PHOTO`, зокрема `image_url` і параметри знімка. |
| `TagService` | Логічний сервіс | Координує додавання тегів і пошук дописів за тегом. |
| `TagRepository` | Доступ до даних | Отримує та зберігає записи `TAG` і зв'язки тегів відповідно до обраної моделі даних. |
| `CommentService` | Логічний сервіс | Координує додавання та отримання коментарів. Коментарі присутні у вимозі FR-5 і Gherkin, але відсутні серед сутностей ER-моделі. |
| `CommentRepository` | Доступ до даних | У запропонованій взаємодії відповідає за збереження та отримання коментарів; потребує сутності/таблиці коментарів у моделі даних. |

**Примітка щодо імен:** `Photographer` та `User` - різні ролі актора в діаграмах, а не дві різні сутності. Обидві відповідають сутності `USER`.
