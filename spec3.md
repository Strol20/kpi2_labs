# Специфікація Use Cases та сценаріїв для Sequence Diagram

## 1. Загальні учасники

Учасники нижче є логічними ролями для Sequence Diagram. Інтерфейс, сервіси та репозиторії деталізують взаємодію, але не є новими сутностями ER-моделі.

| Учасник | Тип | Відповідальність |
|---|---|---|
| `Photographer` | Актор | Створює дописи, прикріплює фотографії та додає теги. |
| `User` | Актор | Відкриває дописи, переглядає фотографії й коментарі, шукає дописи. У сценаріях перегляду це може бути той самий користувач форуму. |
| `ForumUI` | Інтерфейс | Приймає дії користувача та показує результат. |
| `PostService` | Логічний сервіс | Координує створення, публікацію, отримання та пошук дописів. |
| `PhotoStorageService` | Зовнішня система | Зберігає передані фотографії та повертає посилання на них. Назва відповідає актору «Сервіс зберігання зображень» зі `spec2.md`. |
| `PostRepository` | Доступ до даних | Зберігає та отримує записи `POST`. |
| `PhotoRepository` | Доступ до даних | Зберігає та отримує метадані `PHOTO`, зокрема `image_url` і параметри знімка. |
| `TagService` | Логічний сервіс | Координує додавання тегів і пошук дописів за тегом. |
| `TagRepository` | Доступ до даних | Отримує та зберігає записи `TAG` і зв'язки тегів відповідно до обраної моделі даних. |
| `CommentService` | Логічний сервіс | Координує додавання та отримання коментарів. Коментарі присутні у вимозі FR-5 і Gherkin, але відсутні серед сутностей ER-моделі. |
| `CommentRepository` | Доступ до даних | У запропонованій взаємодії відповідає за збереження та отримання коментарів; потребує сутності/таблиці коментарів у моделі даних. |

**Примітка щодо імен:** `Photographer` та `User` - різні ролі актора в діаграмах, а не дві різні сутності. Обидві відповідають сутності `USER`.

## 2. Use Cases

### UC-01 - Публікація допису без фотографій

- **Gherkin:** `Публікація допису без фотографій` (`@US-1 @FR-1`).
- **Функціональна вимога:** FR-1 - публікація допису.
- **Основний актор:** фотограф (`Photographer`).
- **Мета:** опублікувати текстовий допис без прикріплених фотографій.
- **Передумова:** фотограф має доступ до інтерфейсу форуму та створює допис із назвою/текстом «Моя перша зйомка».
- **Результат:** допис «Моя перша зйомка» збережений і доступний для перегляду на форумі.

**Основний сценарій:**

1. Фотограф створює допис «Моя перша зйомка».
2. Фотограф ініціює публікацію допису.
3. `ForumUI` передає дані допису до `PostService`.
4. `PostService` зберігає допис через `PostRepository`.
5. `PostService` повертає результат успішної публікації до `ForumUI`.
6. `ForumUI` повідомляє фотографа, що допис опубліковано.
7. Допис «Моя перша зйомка» доступний для перегляду.

**Учасники діаграми:** `Photographer`, `ForumUI`, `PostService`, `PostRepository`.


### UC-02 - Публікація допису з фотографіями

- **Gherkin:** `Публікація допису з фотографіями` (`@US-2 @FR-2 @FR-3 @FR-4`).
- **Функціональні вимоги:** FR-2 - додавання фотографій; FR-3 - збереження фотографій; FR-4 - перегляд дописів.
- **Основний актор:** фотограф (`Photographer`).
- **Зовнішній учасник:** сервіс зберігання зображень (`PhotoStorageService`).
- **Мета:** опублікувати допис «Захід сонця» з двома фотографіями.
- **Передумова:** фотограф створив допис «Захід сонця» та додав файли `sunset-1.jpg` і `sunset-2.jpg`.
- **Результат:** обидві фотографії збережені зовнішнім сервісом, пов'язані з дописом, а сам допис доступний для перегляду з фотографіями.

**Основний сценарій:**

1. Фотограф створює допис «Захід сонця».
2. Фотограф прикріплює `sunset-1.jpg` та `sunset-2.jpg`.
3. Фотограф ініціює публікацію.
4. `ForumUI` передає дані допису та фотографії до `PostService`.
5. `PostService` зберігає допис через `PostRepository`.
6. `PostService` передає кожну фотографію до `PhotoStorageService`.
7. `PhotoStorageService` зберігає файл і повертає посилання на нього.
8. `PostService` зберігає метадані фотографії та її зв'язок із дописом через `PhotoRepository`.
9. Кроки 6–8 повторюються для обох фотографій.
10. `PostService` повертає результат публікації до `ForumUI`.
11. `ForumUI` показує фотографу опублікований допис із двома фотографіями.

**Учасники діаграми:** `Photographer`, `ForumUI`, `PostService`, `PostRepository`, `PhotoStorageService`, `PhotoRepository`.

### UC-03 - Перегляд опублікованого допису з фотографіями

- **Gherkin:** `Перегляд опублікованого допису з фотографіями` (`@US-3 @FR-4`).
- **Функціональна вимога:** FR-4 - перегляд дописів.
- **Основний актор:** користувач (`User`).
- **Мета:** відкрити допис «Захід сонця» та побачити прикріплену фотографію.
- **Передумова:** на форумі вже опубліковано допис «Захід сонця» з фотографією `sunset-1.jpg`.
- **Результат:** користувач бачить допис «Захід сонця» та фотографію `sunset-1.jpg`.

**Основний сценарій:**

1. Користувач відкриває допис «Захід сонця» через `ForumUI`.
2. `ForumUI` передає запит до `PostService`.
3. `PostService` отримує дані допису через `PostRepository`.
4. `PostService` отримує пов'язані фотографії через `PhotoRepository`.
5. `PostService` повертає дані допису та фотографії до `ForumUI`.
6. `ForumUI` відображає допис «Захід сонця» і фотографію `sunset-1.jpg`.

**Учасники діаграми:** `User`, `ForumUI`, `PostService`, `PostRepository`, `PhotoRepository`.
