# EARS-вимоги: форум фотографів

Вимоги сформовано на основі [README.md](./README.md) та [spec.md](./spec.md). Формулювання використовують шаблони EARS: постійні вимоги, вимоги за подією та вимоги за умовою.

## Функціональні вимоги

| ID | Тип EARS | Вимога | Трасування |
|---|---|---|---|
| EARS-1 | Постійна | Система повинна надавати користувачеві змогу переглядати опубліковані дописи. | FR-4 |
| EARS-2 | Постійна | Система повинна надавати користувачеві змогу переглядати коментарі до допису. | FR-5 |
| EARS-3 | За подією | Коли користувач створює допис і надсилає його на публікацію, система повинна опублікувати цей допис. | FR-1 |
| EARS-4 | За умовою | Якщо користувач додає до допису одну або кілька фотографій, система повинна передати їх сервісу зберігання зображень. | FR-2, FR-3 |
| EARS-5 | За умовою | Якщо сервіс зберігання зображень успішно зберіг фотографії, система повинна пов’язати їх із відповідним дописом і опублікувати допис. | FR-3 |
| EARS-6 | За умовою | Якщо до допису прикріплено фотографії, система повинна відображати їх під час перегляду допису. | FR-4 |
| EARS-7 | За подією | Коли користувач надсилає коментар до допису, система повинна зберегти та показати цей коментар біля відповідного допису. | FR-5 |
| EARS-8 | За умовою | Якщо користувач додає теги до допису, система повинна пов’язати ці теги з дописом. | FR-6 |
| EARS-9 | За подією | Коли користувач шукає дописи за тегом, система повинна показати дописи, позначені цим тегом. | FR-6 |
| EARS-10| За подією | Коли користувач надсилає скаргу на допис, система повинна передати цей допис у чергу модерації.| FR-7|
